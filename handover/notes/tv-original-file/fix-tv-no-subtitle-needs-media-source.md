## Line
- **Original file only on the TV (2026-10-23, built, not yet run on the real TV)**: steps 1-3 of the plan above. Server: `TV_PROFILE` lists truehd, mlp, dts, dca, pcm and alac and allows 400 Mbps; `stream_for()` for the TV never converts: it returns the static file URL plus `audio_order` (0-based position of the chosen audio track in the file), ignores the viewer's quality cap and never burns in picture subtitles (subtitle work is a later PR). If Jellyfin cannot give the original, `/api/nl/play` answers 415 `{detail, can_convert: true}` and the TV player page shows the reason with the button "Play a converted copy (lower quality)" (a normal D-pad-focusable button on the error card); it repeats the request with `allow_conversion=1`, which brings back the old conversion path (Labiba chose this, 2026-10-22). Browser and Chromecast unchanged. App: **bridge v5** adds `setAudioTrack(order)` (select the n-th audio track group, no reload; `play()` json carries `audioOrder`; v4 calls still work and player-core.js uses it only when `version() >= 5` on a `file` stream). Sound: Media3 `DefaultRenderersFactory` with `EXTENSION_RENDERER_MODE_ON` (platform decoders and HDMI passthrough first, FFmpeg after) in `NlRenderersFactory.kt`; when the output is stereo, 5.1/7.1 PCM is downmixed by `AudioDownmix.kt` (BS.775, centre 1.0, surrounds 0.707, LFE dropped, then the whole mix at -3 dB so dialogue sits at 0.707; rare full-scale peaks are clamped by Media3's 16-bit mixer). FFmpeg decoder: `org.jellyfin.media3:media3-ffmpeg-decoder:1.5.0+1` from Maven Central (newest release for Media3 1.5.x; its .so contains the truehd, mlp, dca, ac3, eac3, flac and alac decoders). Video: `VideoSupport.kt` plays Dolby Vision profile 7 on the HEVC decoders (HDR10 base layer; other profiles untouched) and `PlayerController` asks the display for a mode whose refresh rate is a multiple of the film's frame rate, restoring the old mode when playback stops. JUnit tests for the three pure functions are in `tv-app/app/src/test`, run by CI (`testDebugUnitTest`). Not done: disk read-ahead. Fix 2026-10-27: `setAudioTrack(order)` picked the n-th audio group in Media3's list, but Media3 lists groups renderer by renderer, so a track only the FFmpeg decoder plays (TrueHD, DTS-HD) sits after all the others; on "Michael" choosing Italian played Hindi. `fileOrder()` (PlaybackLogic.kt) now puts the groups back in file order by their track number before picking. Fix 2026-10-28: for the TV, PlaybackInfo is now asked with `SubtitleStreamIndex=-1`; left unset, Jellyfin judged the file with its own default subtitle, and a picture subtitle file next to the film (.idx/.sub, .sup) cannot be sent beside it, so "5 Centimeters per Second" got 415 (SubtitleCodecNotSupported, plus the container and audio reasons of the conversion it fell back to). Fix 2026-10-28 (2): Jellyfin 10.11 applies the audio and subtitle choice only to the media source the request names (`MediaInfoHelper.SetDeviceSpecificData`), so the -1 was ignored until `MediaSourceId` was sent too; the TV now sends it (the item id, or the source id Jellyfin answers with), also for the converted copy, which otherwise tried to burn in Jellyfin's default subtitle (the broken .sub made 5 Centimeters' conversion fail).
